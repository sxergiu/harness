# 0.4.0

Four features and six fixes. Most of the fixes were found in the first live run on Windows,
and none of them was visible to CI, which never starts an agent or talks to a live Herdr.

Read the first two first. On a machine whose Claude Code settings never allowed the agents'
tools, every agent stopped at every edit and command; `harness init` now allows them. And on
Windows, every agent the cockpit started was running without most of its rules.

The other features are on every platform: the agent header says what an agent is running
rather than what it last ran, the settings screen can hold the machine's default model, and a
code block in an agent's reply can be run from the feed.

## Agents no longer stop to ask before every edit and command

`harness init` now adds `Write`, `Edit` and `Bash` to `permissions.allow` in
`~/.claude/settings.json`, plus `PowerShell` on Windows, where Claude Code runs shell commands
through that tool as well. The same grant is a button under ⚙ → **PERMISSIONS**, which also
says whether it is in place.

- Only missing entries are appended. Nothing of yours is removed or reordered, other keys are
  untouched, and `Bash(*)` already counts as all of `Bash`.
- A whole-tool `deny` or `ask` still wins over the grant, and is named rather than removed. A
  narrowed rule such as `Bash(rm:*)` is a deliberate restriction and is left alone silently.
- A settings file that is not JSON, or whose `permissions` this would have to guess about, is
  left alone and reported. A missing one is created at mode 0600.

Before, the docs assumed `settings.json` already allowed these tools, and nothing installed
that. On a machine where it did not, every agent the cockpit started stopped at every tool
call, which reads on the board as a column of blocked agents. Re-run `harness init` after
upgrading.

## Windows: agents started without most of their rules, and every one opened on "X,"

Straight double quotes are now turned into curly ones before the system prompt is passed to
an agent. They read the same to the model and mean nothing to any shell. The conversion runs
on the final text, so it also covers a human's own `~/.harness/rules.md` and the aside's
prompt.

The rules go to each agent as one `--append-system-prompt` argument, and Herdr starts the
agent by typing the command at a shell. On Windows that shell is Windows PowerShell 5.1,
which wraps a native argument in double quotes **without escaping the ones inside it**, and
rule 7 contains `("was X, now Y")`.

Measured on the live agents' command lines: the argument ended at `(was`. `X,` arrived as
`claude`'s positional prompt, so every agent began its session with a stray "X," the human
never typed. Everything after that point was dropped without any error: rule 8, and in a
checkout with git delegated, the amendment granting it. Those agents only ever saw rule 1's
"NEVER commit or push", so they refused. The grant was stored correctly the whole time
(`~/.harness/projects.json`) and the amendment was on the command line; it just never reached
the system prompt. A test pins that the prompt carries no straight `"` and still ends with
the git amendment.

**macOS and Linux were never affected**: their shells quote the argument correctly. Agents
already running on Windows were started with the truncated prompt and keep it, so restart
them.

## Conversations Herdr failed to restore stay on the board, with a resume button

A conversation whose restore failed now stays on the board as **not running**, with its feed,
changelist, todo and context intact, and a **resume** button that starts it again in the same
pane. Before, it vanished from the cockpit with nothing saying so.

Herdr restores a saved session by typing `claude --resume <id>` into a fresh shell. When that
fails, the pane is left as a bare shell that still holds the session, and the board dropped
every pane without a running agent. Measured on Windows: Claude Code updated itself across a
Herdr restart, its `claude` shims were deleted and recreated over about 10 seconds, and Herdr
typed into ten panes inside that window. All ten answered `not recognized`, and all ten
conversations disappeared from the board while their transcripts and panes were intact. This
is a race between npm relinking its bins and Herdr's typing, so it can happen on any
platform, and Herdr has no setting that prevents it.

- **Resume is pressed by you, never done on its own.** A heartbeat can land between Herdr's
  restore and its own typing, and resuming then would start one session twice in one pane.
- **A resume carries the cockpit's rules and `--model`.** Herdr's own restore types a bare
  `claude --resume`, so even a restore that works brings agents back without either.
- A failed resume leaves the pane open, with the reason in the error.
- Panes in `aside` and `usage` tabs are never shown this way. A dormant aside on the board
  would claim its parent's whole changelist.

## Starting an agent from a space no longer stops at the trust dialog

Starting an agent from a space now marks the space's directory as trusted first, so the agent
does not sit at Claude Code's "Is this a project you created or one you trust?" dialog,
where it reads as idle on the board. Pressing start is the decision the dialog would ask for
again. The home directory and anything above it are never trusted this way, because trust is
inherited by every folder below.

On Windows, no trust the cockpit granted ever took effect, including for its own
`~/.harness`. It wrote the key as `C:\Users\…`, while Claude Code reads and writes
`C:/Users/…`, with forward slashes and an upper-case drive. The key is now written in Claude
Code's spelling.

## Windows: the cockpit could not reach Herdr

The client now connects to Herdr's named pipe, prefixing `\\.\pipe\` on Windows unless the
name is already in that namespace.

`herdr status server --json` reports the endpoint as a bare path, while the server listens on
the named pipe of that name. Connecting to the path reached a 25-byte regular file and failed
with `ENOTSOCK`.

## Windows: the accounts panel said `claude` was not on PATH

`claude` is now run through `cmd.exe` on Windows. Every caller passes literal arguments, so
nothing needs quoting.

An npm-installed `claude` on Windows is `claude.cmd`, which `execFile` neither resolves nor
runs without a shell, so the panel reported a missing CLI on a machine that had one.

## A log that says why the cockpit stopped

`~/.harness/harness.log` now records why the process stopped: the signal or route that shut
it down, an uncaught exception with its stack, and the exit code. Closing the console window
(`SIGHUP`, which Node maps to the console's close event on Windows) now shuts down cleanly
and releases the lock instead of leaving it behind.

Before, a crash went only to the stderr of the window that started the cockpit, which is
usually gone by the time anyone asks why it stopped. Measured: a cockpit that vanished
mid-session left a log ending at `herdr connected` and a lockfile naming a pid already reused
by another process.

## The agent header says what an agent is running, not what it last ran

The model label in the agent header now reads the alias the pane was asked to run (from the
header's picker, or the `--model` the cockpit started it with) and refines it with the
transcript once a request on that family has run:

```
hand-started, never asked      ->  opus-5
just switched to sonnet        ->  sonnet
...and its next request ran    ->  sonnet-5
switched to 1M, request ran    ->  opus-5 1M
switched DOWN off 1M           ->  opus-5
```

The effort level beside it follows the same rule, and the picker ticks the alias the pane is
on. `fable` is marked with a ⚠ in the picker: it costs twice what opus does per token, so it
draws the limit bars down fastest.

Before, the label was the model id of the newest request in the transcript. That is past
tense, and it cannot spell `[1m]`, because `opus` and `opus[1m]` both record
`claude-opus-5`. So a switch between those two never showed on screen at all, while the
context meter beside it changed window from 1M to 200k, and every other switch showed only
after the agent's next request.

An alias is a request rather than an outcome, so the cockpit **drops one as soon as the
pane's own requests contradict it**: an alias the account lacks is refused in the pane while
the agent carries on unchanged, and a `/model` typed in the pane moves the session without
telling the cockpit. Only a turn **opened after** the switch counts as evidence. A switch sent
to a busy agent waits for the current turn to end, and that turn's remaining requests land
after the click on the old model; counting them would drop every switch made at a working
agent before it had run. An effort level is also answered by the cap Claude Code applies, so
`max` asked of a model that stops at `high` reads `high` after its first request.

## The machine default model can be held from the settings screen

A new **MACHINE DEFAULT** section on the settings screen pins the `model` key in
`~/.claude/settings.json`. That is the model every agent started by hand runs on, and the one
the context meter falls back to for an agent the cockpit knows nothing else about. Once
pinned, the cockpit puts the key back on its next heartbeat whenever anything moves it, so a
`/model` typed in a pane moves that session and no longer moves the machine.

- Stored in `~/.harness/claude-model`. **Out of the box nothing is pinned**, and an
  unpinned install leaves the file exactly as 0.3.0 did.
- It writes only when the file has drifted from the pin, never on every heartbeat, because
  every running agent writes that file too.
- Unpinning stops defending the key and leaves its value where it is. It does not clear it.
- A missing `settings.json` is now created at mode 0600 when a pin needs to write it. One
  that is not valid JSON is still left alone.
- This is a separate setting from the cockpit's own `--model` (`~/.harness/model`), which
  applies only to agents the cockpit starts.

Without a pin, a `/model` typed in a pane, or a harness restarted while a per-agent switch was
being held, moved the machine default with nothing to put it back. Measured: the file held
`haiku` while `~/.harness/model` said `opus[1m]`, so every pane whose in-memory alias had
been lost to a restart fell back to a 200k window, and the context meter jumped about 5× on
sessions under 200k.

## Run a code block from an agent's reply

A `bash`, `sh`, `shell`, `zsh` or PowerShell block in a live agent's reply now has a **▶ run**
button. It runs the block through Claude Code's shell mode (`! cmd`) in that agent's pane, so
the output lands in the agent's own context and transcript. The box shows the output as it
arrives, then as recorded once the run has finished, and the feed shows each run as one entry
with its command and output. Before, a `!` run typed in the pane showed in the feed as two
turns of raw XML.

- **Every run costs the agent a model turn**: it answers the output without being asked.
- **No exit code is recorded anywhere**, so a run shows what was printed and never claims
  success or failure.
- On Windows, `!` runs Git Bash, so a PowerShell block is sent as
  `powershell -NoProfile -Command '…'`.
- `console` blocks get no button: they are sessions, and running one would run its output.
- A run sent to a busy agent waits behind its turn and shows no output until it starts.

The check that presses Enter on a prompt that did not submit now also recognises the box in
shell mode, which Claude Code draws with `!` and no `❯`. Before, a stalled `! cmd` could sit
in the box unsent.

## Known, and not fixed here

- **Only the straight double quote is handled.** A prompt whose last character is a backslash
  would still confuse Windows argument parsing, because the backslash escapes the closing
  quote. The shipped rules do not end that way, and a `rules.md` would have to end that way
  on purpose.
- **A pin puts the default back; it does not lock it.** Nothing stops Claude Code writing the
  key, and while the harness is down nothing puts it back. `effortLevel` is not pinnable.
- **Claude Code's own `Switch model?` confirm is not seen.** A cross-family switch at an agent
  that has already worked raises it, and until the human answers it in the pane or the
  blocked panel, the header reads as the switch they asked for.
- **What the cockpit knows about a pane still does not survive a restart.** The alias a pane
  was switched to, or started with, is in memory and dropped with the pane. After a restart
  the label falls back to the transcript, and the meter falls back to the machine default,
  which is what a pin is for.
- **Several new screens have not been looked at in a browser**: the MACHINE DEFAULT and
  PERMISSIONS settings sections, the ▶ run box, and the not-running strip with its resume
  button. Each is covered by the typecheck and by tests of the logic under it, not by anyone
  looking at it.
- **The Herdr detection rule still does not install on Windows.** `harness init` looks for
  Herdr's manifest under `~/.local/state/herdr`, and on Windows it is under
  `%LOCALAPPDATA%\herdr\agent-detection`, so Windows reports `no-remote`.
- **A failed launch can report the wrong line.** In a deep directory the PowerShell prompt
  wraps over two lines, and the error can quote the second half of the prompt instead of
  `claude`'s own message.
- Everything 0.3.0 said about its own limits still holds, with one exception: a cockpit has
  now run against a live Herdr on Windows, which is where most of the fixes above come from.
