# 0.5.0

Three features and one fix.

Read the first two first. On Windows, a start whose `claude` the shell could not find left a
pane nothing on the board showed, holding an agent name every later start in that space was
refused. And the prompt box has changed for everyone: it now sizes itself to its text, and
the lock, peek and drag are gone.

The other two are additions: copying text selected in the agent view, and the running version
on the settings screen.

## A launch that never came up no longer holds its agent name off-screen

A start that died now fails with its pane closed. If the cockpit cannot tell, the pane shows
on the board as **not up after 30s**, with a close button.

Measured on Windows: a start whose `claude` the shell could not find
(`Start-Process : … cannot find the file specified`) stayed `launch_pending` in Herdr
indefinitely, with no agent kind. The cockpit read that as a slow start and returned the pane,
and the board dropped it as a bare shell. Herdr kept holding its name, so every later start in
that space failed `agent name … is already used`, and the error named a pane nothing on screen
showed.

- A launch still pending after 20s counts as dead when nothing came up as an agent and the
  pane's last line is a shell prompt with no `─` rule above it. A live Claude Code always draws
  its rules. When the pane cannot be read, the launch still counts as started: closing a
  running agent is the worse mistake.
- New agent names avoid every name Herdr holds, not only the board's rows. A resume does the
  same, since a resume that died leaves its name held the same way.
- A stalled row is never added to RECENT and never announced as an exit. It says "not up after
  30s" rather than "never started", because elapsed time is all the cockpit knows.

**Known, and not fixed here.** Only the decline path of the shell check rests on a real pane
tail; the live-agent cases are constructed fixtures. A resumed agent's name is now normalised,
so a hand-typed name with capitals or spaces comes back lowercase and hyphenated.

## The prompt box sizes itself to its text

The prompt box is one line when it holds one, grows as the text wraps up to 60% of the window's
height, and scrolls past that. The lock/free toggle, the right-click peek and the
drag-to-resize border are gone, along with the stored `harness.promptMode` preference. Its
shut height still matches the usage dock beside it.

The `/goal`, `/feature` and `/investigate` field under the header grows with its text the same
way, and keeps the browser's corner grip for dragging it taller.

**Known, and not fixed here.** Firefox does not support `field-sizing`, so there the box stays
one line and scrolls, and nothing can make it taller. The drag was the fallback that worked in
every browser.

## Copy text selected in the agent view

A new `⧉` switch in the board header copies whatever you select in the agent view as soon as
you release the mouse, the way a terminal does. It is **off by default**, because it
overwrites the clipboard, and it is remembered per browser.

- Only a selection that changed during the press is copied, so clicking a button with text
  already selected copies nothing.
- Both ends of the selection must be inside the agent view: a drag that runs onto the board
  is not copied. Text selected inside the prompt box or another field is never copied.
- A label at the pointer says `copied`, or shows the clipboard error in red.

## The settings screen shows the running version

The settings header reads `settings  harness 0.5.0`, and the startup line in the terminal reads
`[harness] v0.5.0 http://127.0.0.1:4373`.

The version is read once, at start, from the same manifest `harness --version` reads. So an
upgrade installed under a running cockpit shows the old version until that cockpit restarts,
which is the version actually running. Nothing compares it against npm to say an update is
available.

## Not verified

None of these four has been tried in a browser: no running cockpit was restarted on this code.
Lint, typecheck, tests and build pass on macOS, Linux and Windows.
