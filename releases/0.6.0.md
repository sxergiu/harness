# 0.6.0

Nine features and one fix.

Read the first two first, because they change what two existing buttons cost and do. **↻ now
spends a model turn**: besides resyncing the board, it starts a fresh agent on haiku and sends
it "ping", which wakes agents stalled on API timeouts. And **▶ on a code block no longer runs
in the agent**: it runs in a fork of the agent's session, which explains the result, so the
agent itself neither spends a turn on it nor sees the output.

Then the fix: Enter in the blocked panel no longer throws away every answer of an
AskUserQuestion. The rest are additions.

## ↻ pings a fresh agent, which wakes agents stalled on API timeouts

↻ still resyncs the board. It now also starts a brand-new `claude` named `harness-ping` in
`~/.harness`, on **haiku**, sends it "ping", and closes it once it has answered. Stalled agents
then resume on their own.

That this works is the human's observation. Why it works is inferred, most likely a fresh
process refreshing the account's shared credentials, and nothing depends on the reason. A
timeout is retried on screen and written to no transcript, so the recovery itself is never
observed. The pane is never reused, since a fresh process is the point, and one left behind by
a crashed harness is closed rather than adopted.

Every press costs one haiku turn on the signed-in account. Herdr's resync on its own is still
`POST /api/refresh`.

## ▶ runs go to a run fork, beside a column of files

A ▶ from an agent's reply goes to a **run fork**, a second fork of the agent's session
(`aside-<pane>-run`). It runs the command in its own shell mode, explains the output and
proposes the next command, which has its own ▶. Runs queue one at a time and still ask for
confirmation before each.

The fork and the file viewer are columns beside the tabs, resizable and remembered per pane.
Like the aside, the run fork is kept off the board and never diffed (invariant 18). Both forks
close when the parent's session ends.

**Known, and not fixed here.**
- The fork is taken at the first ▶ and later runs are explained against that copy, so it does
  not see edits the agent made since. `refork` takes a fresh one.
- A run's output no longer reaches the agent. Paste it into the prompt when the agent needs it.
- A run that never ends (`npm run dev`, `tail -f`) holds the queue until × closes the fork.
- Two viewers starting the same fork at once can collide on its name. The second start fails
  with "agent name … is already used".

## Enter in the blocked panel no longer declines every AskUserQuestion answer

Measured on Claude Code v2.1.309: Enter on the empty "Type something." row of a multi-question
AskUserQuestion ends the whole dialog as "User declined to answer questions", discarding every
answer already given on the other tabs. The panel now refuses that one Enter and says why.
Typing an answer and sending it is unchanged.

The check reads only the last `❯` line of the visible pane, and only to refuse. A restyled
dialog makes it quiet, not wrong.

## A running summary of each conversation

A **summary** tab holds a short brief of the conversation, under Discussed, Decisions and Open
items. It is written by a haiku agent of the harness's own, `harness-summary` in `~/.harness`,
started with the Read tool only and none of your MCP servers. The server writes the result to
`~/.harness/summaries/<session>.md`; the summarizer never writes anything.

**It runs only while the tab is open.** Every update is billed to the account, so nothing is
spent on a conversation nobody is reading, and a tab on an idle conversation costs no job. After
a failed job, updates for that session stop until ↻ in the tab, because what fails one job (a
dialog, a signed-out account) fails the next.

Run live against a real agent: a correct brief in 18s, and nothing queued when nothing new had
been said.

**Known, and not fixed here.** A compaction's "This session is being continued…" summary
reaches the summarizer as something the human said. Summary files are never deleted.

## Choose a space's folder in the system dialog

A space's folder can be picked in the operating system's folder dialog instead of typed. A
picked folder goes through the same check as a typed one.

On macOS the dialog is hosted by System Events, because a dialog opened by the server itself
appears behind the browser. Exercised by hand on macOS 26.4: it opens in front; Choose returns
the folder; Cancel and closing it return nothing; and a cancelled request (tab closed,
shutdown) closes the dialog.

**Known, and not fixed here.** On Windows and Linux the dialog has never been opened. Linux
needs `zenity`. On Windows, after a self-update the server runs without a console, so the dialog
may come with a visible PowerShell window.

## Install a newer harness from the settings screen

When npm has a newer `@sxergiu/harness`, the settings screen offers **update**. It installs
that version globally and restarts into it, and the open tabs reload onto the new page. It is
offered only to a global npm install; a checkout is told to update itself.

- Opening settings asks `registry.npmjs.org` for the latest version. No other part of the
  harness makes a request to the internet.
- The version is asked of the registry again on the server, never taken from the browser, and
  must be plain semver before it reaches the install command.
- What npm installed is read back before restarting. A mismatch leaves the running harness in
  place.
- The restarted harness runs detached from the terminal it was started in, so ctrl-C there no
  longer ends it. `harness stop` does.
- If it does not come back, the settings tab says so after 45s, and the new process's stderr is
  in `~/.harness/restart.log`.

**Known, and not fixed here.** The install-and-restart has not been run end to end against a
registry. An install killed part-way leaves the running harness on disk files of the new version
until it is restarted.

## Bare file references open the file they name

A file named by its tail in an agent's prose, such as `index.ts` meaning `server/src/index.ts`,
now opens. The agent's own writes are tried first, then the checkout's files as `git ls-files`
lists them. When several files match, the panel lists them instead of guessing. Measured: 146 of
293 file links in three repos' prose resolved to nothing before.

Every candidate passes the same containment check as any other file the panel opens. This is
the first time the file route runs a process (`git`, with no shell).

## URLs in an agent's output are links

URLs in prose, tool output, shell output, errors and subagent results open in a new tab, as do
markdown `[label](url)` links. Only `http` and `https` can become links.

## The prompt box locks while an agent starts, and keeps unsent drafts

The prompt box no longer takes text it cannot send. It locks while an agent is starting (Herdr
refuses prompts for ~3.7s after a start), while the cockpit is offline, and while an action is
in flight. Clicking a space's `+` now shows the agent starting, instead of leaving the previous
agent on screen to type into. Drafts are kept per pane across `/clear`, a fresh launch and a
page reload.

## Row shades survive a restart

A row's shade is kept in `~/.harness/shades.json`, so it survives a harness restart. It is also
meant to survive a Herdr restart, which has not been tried. Shades are keyed on the pane id and are not cleared when an agent goes, which is
deliberate: a pane id reused for a new agent can come back wearing the last one's colour. A
shade makes no claim about the agent, so the cost is a wrong colour on a row.
