# 0.7.0

Four features and one fix.

Two things change for everyone on upgrade. Agents started from now on are told to hand you
commands as `bash` blocks, so ▶ appears on far more of them. The theme and copy-on-select
are held by the server, so the choice is the same in every tab and on every origin.

Auto-accept and the folder list are opt-in, and nothing changes until you tick one. Read that
section before you do: auto-accept removes every permission prompt for agents in that checkout.

## Agents hand you commands as bash blocks, so ▶ can run them

A new rule 9 tells every agent the cockpit starts to put each command you should run in its
own fenced block tagged `bash`, with no prompt in front and no output under it. ▶ only appears
on a tagged block. In two weeks of transcripts, 60 of 83 command fences were untagged and had
no ▶. Untagged fences are not guessed at, because they are as often output or a file tree.

Agents already running keep the rules they started with. A `~/.harness/rules.md` that replaces
the rules wholesale replaces this one too.

## Preferences live on the server, and agents can skip the asking per checkout or folder

**The theme and copy-on-select** are kept in `~/.harness/prefs.json` and pushed to every tab.
Before, they were in browser storage, which is per origin: the dev page on 4374, the built one
on 4373, and `localhost` against `127.0.0.1` each kept its own copy. A choice this browser had
already made is carried up the first time the server has none, so the upgrade forgets nothing.
Until a theme is picked it still follows the OS.

**Auto-accept is a per-checkout grant** beside git delegation. It is ticked in ✎ on a space,
shown as `auto` in the space header, and revoked in ⚙ CHECKOUTS.
- Agents the cockpit starts or resumes in that checkout run with `--permission-mode
  bypassPermissions`. Asides, run forks and the cockpit's own agents are never started with it.
- Ticking it writes `skipDangerousModePermissionPrompt: true` to `~/.claude/settings.json`,
  because otherwise Claude Code stops every bypass-mode agent at a warning. That key is
  machine-wide, is not removed when the grant is revoked, and also silences the warning for
  agents you start by hand.
- A revoke that cannot be saved is refused with an error. The grant stays in force rather than
  coming back silently at the next restart.

**⚙ FOLDERS** adds entries to `permissions.additionalDirectories` in `~/.claude/settings.json`,
the folders outside its own directory that an agent may use without asking. The setting is
user-level, so it covers every Claude Code session on the machine. For that reason the home
folder and anything above it are refused. The cockpit removes only the entries it added; your
own are shown as "yours", with no remove button.

**Known, and not checked here.**
- Whether a fork or a `--resume` of a bypass-mode session inherits that mode is not measured.
  Asides and run forks are never passed the flag, but Claude Code records the mode in the
  transcript. Check by hand before relying on a fork of an auto-accept agent to ask.
- None of this has been run against a live cockpit or rendered in a browser. The parse, the
  bypass flag and the folder merge are covered by tests.

## ⚙ is marked when a newer harness is out

The server asks npm for the latest version at start, then again once its last answer is a day
old, or an hour old if that answer was a failure. The check is timed by the wall clock rather
than a 24h timer, because a timer stops while a mac sleeps. When a newer version is out, ⚙
shows an emerald dot. The settings line shows the result with the time of the last check, and
a `check` button asks again.

A failed check keeps the last version found, so a registry blip does not take the dot away.
A checkout sees the dot too. The update button still installs over a global install only, so
a checkout is told to update itself.

## ⤒ in the fork panel

The aside and the run fork get the feed's ⤒. It jumps to your newest question, puts it at the
top of the panel and flashes it, and the panel follows each new question as it lands. The
feed's behaviour is unchanged; both now share one implementation. Not yet seen in a browser.

## Dependency advisories in a clone

`npm audit` reported 7 advisories in a clone of the repository: `fastify`, `fast-uri`,
`brace-expansion`, `vite`, `source-map-js` and `concurrently`'s pinned `shell-quote`. Every fix
was inside a range the manifest already declares, so only `package-lock.json` changed.

**A published install was never affected.** Only `dist` is published, and a global install
resolves its dependencies fresh; a real 0.6.0 install already had the fixed versions.

**Known, and not fixed here.** Since then `npm audit` reports three moderate advisories in
`glob` and `minimatch`, reached through `@fastify/static`. The fixed `glob` is 14.0.2 or later,
outside the `^13` that `@fastify/static` 10.1.8 allows, and the only fix npm offers is a
downgrade to `@fastify/static` 6. Neither advisory is reachable here: `@fastify/static` calls
`glob` only with `wildcard: false`, and the harness registers it with the default.
