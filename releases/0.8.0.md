# 0.8.0

Three features and four fixes, every one of them an open issue: #41 to #48.

Two things change for everyone on upgrade. The ⤒ button beside the prompt box is now ↑ and ↓,
stepping between your prompts rather than jumping to the newest. And agents started from now
on are told two more things: keep table cells short, and give the non-interactive form of a
command, since a ▶ run has no stdin.

On macOS the folder dialog now comes to the front. The first press compiles a small applet of
our own into `~/.harness`, which is what makes that possible; read that section before
wondering what `harness-picker` in the menu bar is.

## The macOS folder dialog comes to the front (#41)

**Choose a folder** opened the OS dialog behind the browser, so pressing it looked like
nothing happened. Measured on macOS 26.4 with Chrome in front: the dialog existed in System
Events with `frontmost: false`. Nothing a background process can ask of osascript puts a
window in front — `activate` of System Events (what the code did), `set frontmost` and
`AXRaise` on the dialog's window after it was up, hosting the dialog in Finder, and launching
an applet through `open` all left it behind Chrome.

What does work is a real app of our own that activates itself before showing the dialog. The
cockpit compiles `~/.harness/harness-picker.app` with `osacompile` on first use, and rebuilds
it only when the shipped script changes. It is run by its binary, so cancelling kills the
applet and the dialog goes with it. The answer comes back through a file named in the
environment, as `OK`/path, `CANCEL` or `ERR`/message; an empty answer is a failure and never a
cancel. Verified live through the real route: frontmost while open, gone on cancel, nothing
left behind. While the dialog is up the menu bar reads `harness-picker`.

Not watched: a human's actual click on Choose. Windows and Linux are unchanged.

## Markdown tables render as tables (#42)

A GFM table in the feed was one paragraph of pipes. A run of pipe lines is now a table: the
`|---|` row under the first line makes it the header and sets each column's alignment, cells
keep inline code, bold, links and file links, and `\|` is a pipe inside a cell. A wide table
scrolls sideways in its own box rather than widening the column. This applies everywhere
markdown renders: the feed, the fork panel, the summary tab, subagent output.

Rule 10 asks agents to keep cells to a word, a number or a short phrase, and to give one short
section per row instead of a wide table when a comparison needs sentences. An instruction,
not enforced, like the other rules.

## ↑ and ↓ step between your prompts (#43)

The ⤒ button jumped to your newest prompt only. In its slot there are now two buttons stacked:
↑ goes to the prompt before the one you are on, ↓ to the one after, and ↓ past the newest goes
to the end of the feed. Before any press you count as being at the end, so the first ↑ lands
on your newest prompt as before. The flash still shows where you landed, and a prompt landing
still spotlights itself. The fork panel has the same pair. Feed tab only, as before.

↑ at the first loaded prompt lands on it again; loading earlier turns is still the feed's own
button.

## A run has no stdin, and agents are told so (#44)

Measured by driving a Claude Code 2.1.291 in a pseudo-terminal: inside a bash-mode `!` command
`[ -t 0 ]` is false, fd 0 is the null device, and `read -t 5` returns 1 at once. So a ▶ run
never waits for input: a `[y/N]` takes its default, a password prompt or a login fails
outright. There is no "waiting for input" state to detect and no reply box that could answer
one.

What changed: rule 9 tells agents to give the non-interactive form (`--yes`, `-y`,
`--no-pager`, `--non-interactive`, input from a file) and to say when a command needs a
terminal, so the human runs it in one. ▶'s tooltip and the run panel's empty text say the
same.

## Each weekly usage bar names its limit (#46)

The limits at the foot of the board showed two bars both labelled `week` at different
percentages. Read out of the 2.1.291 binary, the panel draws `Current session`, `Current week
(all models)`, `Current week (Sonnet only)` and a `Current week (<model>)` per model; the
label kept only the first word. The whole heading after `Current` is now the label, lowercased:
`week (all models)`, `week (sonnet only)`. The label column is wider to hold it.

Readings cached on the account rows keep the old labels until the next reading of that
account.

## Task notifications and subagent hand-backs are no longer your prompts (#47)

When a background task finished or a subagent handed back, Claude Code wrote the notice as an
ordinary `user` entry without `isMeta`, so the feed showed it as something you typed, it
opened a turn, and the prompt jump could land on it. Every user entry on 2.1.x carries
`origin.kind`: `human` for the typed prompt, `task-notification`, `peer` with `handback: true`,
and `auto-continuation` for what Claude Code wrote itself. An entry whose kind is present and
not `human` now renders as a muted system line and opens no turn. No `origin`, or one with no
string `kind`, still counts as the human, so an older Claude Code changes nothing.

## A closed conversation keeps its forks, as a fork tab (#48)

Once an agent moved to RECENT its aside and run fork were unreachable, though their
transcripts were still on disk. A closed row now has a fifth tab, **fork**, listing every fork
the agent had in its last session, each showing only the exchange since the fork.

The fork's session is recorded on the parent's row from the heartbeat snapshot, where the
fork's pane carries it like any pane, so this costs no request. It is the one pane-keyed fact
that rides the row into RECENT by design. A refork is appended; `/clear` drops the list. The
read-back resolves the fork's transcript by that session in the parent's directory and
applies the same rule as the live panel: skip what the parent already has, show nothing when
the parent's transcript is gone, and say so when the fork's own transcript was pruned. Forks
stay off the changelist and the contention join.

Forks of conversations closed before this version have no recorded session and show nothing,
which the tab explains. A fork is recorded by the heartbeat after the one that sees it start,
so one closed within about two seconds of starting leaves no record.

## Known, and not fixed here

- None of the browser changes — the tables, the ↑/↓ pair, the fork tab, the wider usage
  label — were opened in a live cockpit. The tables and the button pair were screenshotted as
  static pages with the built stylesheet; the rest rest on the type checker and on tests.
- The `!` runs typed in an agent's own pane, and background runs in their own windows, are
  still not listed in the run panel, and the agent still never sees a run's output.
- PR #50 landed on `master` under its commit subject rather than its title, because GitHub
  takes a one-commit PR's commit message as the squash subject.
